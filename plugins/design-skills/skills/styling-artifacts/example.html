This page sets the house style for the HTML artifacts the Data Science and Analytics team publishes: reports, dashboards, run explorers, review and comparison pages. It ships in the design-skills plugin as the styling-artifacts skill. Claude Code loads the skill on its own when it starts choosing fonts, colours or layout for an artifact, so nobody has to ask for it.

Everything below is live. The toggle in the top bar switches theme. The palette is rust on paper neutrals, with wine, teal and honey for bad, good and caution, and a warm charcoal for dark mode. The type is Archivo, with its wide cut kept for the largest elements. The numbers are sample values.

Foundations

Tokens, type scale, state markers and surfaces. These sections use the side-rail layout: a sticky title and a short note on the left, the material on the right.

Colour

Tokens

The neutrals carry the page. The accent marks the selected row, the winner ring, the primary bar, the button and the link. The three state pairs mark good, caution and bad.

A page does not add colours. A subject with five severity levels maps them onto these three states and neutral.

The hex values are read from the rendered page, so they change with the toggle. Every text colour clears 4.5:1 on the surfaces it sits on, in both themes.

Type

Archivo

Archivo is the only typeface. Hierarchy comes from weight and width: headings are 500 with slightly tight tracking, subtitles and the hero number are 300.

The wide cut (font-stretch: 112%) is used on elements 22px and larger. Below that, the normal width keeps tables dense.

State

State markers

Each state has a shape as well as a colour: good is a filled circle, caution a diamond, bad a filled square, neutral an outlined circle. Chips, table marks, banners and legends all use them, so the page still reads in greyscale or to a colour-blind reader.

Good--ok · survives, passes, clean
Caution--warn · below the bar, assess, partial
Bad--bad · eliminated, blocked, failed
Neutraloutlined muted · unclear, absent, not run

Surfaces

Surfaces

The page sits on --bg. Cards, the top bar and tables sit on --surface with a 1px --line border, a 6px radius and the house shadow. Card footers, code and notes sit on --surface-2. Selected and hovered rows take --accent-wash.

Themes

Light and dark

A viewer arrives in one of three states: light or dark stamped on the root by the host, or nothing, in which case the operating system decides. The stylesheet has a token block for each.

The toggle at the right of the top bar switches from whatever is showing and saves the choice in localStorage as dsa-theme. With nothing saved, the page follows the host.

:root { …light tokens… }
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) { …dark tokens… }
}
:root[data-theme="dark"] { …dark tokens… }

Paste tokens.css in full: it has all three blocks and the base styles. The boot script in head.html stamps a saved choice before first paint, so the page does not flash. The button and its script are in theme-toggle.html.

Where the misses are

49 titles the screen had been quiet about, read in full

Misses concentrate almost entirely on the titles the screen said least about, which is the case for reading those first. On a title already blocked on four concepts, a fifth missed one changes nothing: a reviewer is looking at it anyway.

Absence of a flag on this page is not evidence of absence in the book.

Copy is capped at 64ch. In a lead, it says what the numbers show and where they stop.

About this page

This page ships with the styling-artifacts skill. Every component on it is built from the same tokens.css and components.css that a session pastes into a new artifact, so a change to either file shows up here first. Check both themes before changing a token.

Artifacts are self-contained pages, so the CSS is inlined into each one rather than imported. components.md has the markup for each piece.

The titles, verdicts and numbers are sample values and do not describe a real run.
